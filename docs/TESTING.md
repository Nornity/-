# Проверка прототипа 0.1

Дата: **29 сентября 2026**.

## Подтверждённый результат

Игра запускалась в **настоящем Godot 4.6.stable.official.89cea1439**, WebAssembly, Compatibility / WebGL 2. Не использовались JavaScript-заглушки игровой логики. Проверка GDScript сторонним парсером была дополнительной, не заменяла запуск движка.

Последний автоматический результат:

```json
{
  "engine": "4.6-stable (official)",
  "failed": 0,
  "failures": [],
  "passed": 816
}
```

**816 проверок, 0 ошибок.** Это число отдельных проверяемых утверждений, а не 816 вручную пройденных забегов. Большинство проверок относятся к 64 вариантам генерации лабиринтов. Подробности — `tests/smoke.gd`.

### Что проверяется движком

- 4 сектора × 16 seed: нечётный размер, закрытая граница, связность каждой клетки, отсутствие пересечений предметов/спавнов, доступность всех предохранителей и шлюза.
- Повторяемость генерации по seed; непрерывные пути BFS без прохода сквозь стены.
- Ограничение сложности и размеров бесконечных этажей.
- Безопасное обучение, движение с реальной физикой, приседание, пауза и возобновление.
- Ускоренный спринт, расход стамины до истощения, восстановление порога для нового рывка, разные радиусы шага и усиленный слух монстров.
- Расход шокера, задержка между выстрелами, стоимость перезарядки, автоматическая замена батареи, пустой фонарь.
- Бросок и приземление камня, взаимодействие с предметами без повторной выдачи.
- Слух слепого обитателя, тихий шаг против бега, зрение поздних типов, стены/линия видимости, непривязанное к центрам клеток преследование на четырёхклеточном перекрёстке: физическая проверка на 60 кадрах подтверждает сближение без кружения и возврата в центр клетки; оглушение и восстановление.
- Разрушение хрупкой перегородки; изменение коллизии и карты.
- Условие открытия шлюза, 3D-лифт, результаты, запись времени и открытие следующих секторов.
- Смерть со скримером: уникальный аудиостинг, быстрый крупный выпад с вытянутыми к игроку руками, наведение камеры на лицо без прохода модели сквозь камеру, управляемая вспышка и отсутствие тряски/вспышки в режиме сниженных эффектов; повтор с тем же seed, переход между бесконечными этажами.
- Сохранение/загрузка настроек, открытий и рекордов.
- Сенсорный стик, одновременные движение/бег/обзор, независимое освобождение пальцев, кнопки карты/фонаря/паузы, сброс зажатых действий при паузе.

Во время этих проверок **3D-отрисовка временно отключена**, но физика, GDScript и узлы игрового мира настоящие. Поэтому этот результат **не является тестом FPS**.

## Визуальная и интерактивная проверка

В Chromium 138 / Playwright отдельно запускался обычный режим с включённой 3D-отрисовкой:

- Главное меню с живым коридором, выбор сектора, параметры.
- Старт B3: правильное направление камеры после захвата указателя, фонарь, геометрия, HUD, шокер.
- Захват в 3D WebGL: короткая вспышка, крупный портрет существа, наведение камеры на лицо и резкий рывок перед затемнением.
- Старт T0 через реальные клики меню, движение клавишей W, карта клавишей M, пауза Esc, кнопка продолжения.
- Сенсорная эмуляция 960 × 540: выбор T0 и запуск касаниями, виртуальные кнопки, открытие карты и паузы.

Скриншоты были просмотрены. Примеры находятся в `docs/screenshots/`. В этих прогонах не было сообщений об ошибках движка или JavaScript. Запуск выполнялся с программным WebGL **SwiftShader**, не с реальной видеокартой. Первое построение/отрисовка сцены в такой среде может занять десятки секунд; это не измерение производительности настольной игры. Чувствительность и баланс погони требуют дальнейшего ручного плейтеста.

Браузер выдаёт предупреждение об устаревшем `ScriptProcessorNode` внутри веб-шаблона Godot. При автоматическом тестировании без жеста пользователя также появляется предупреждение политики автозапуска аудио. Обычный запуск из меню начинается нажатием кнопки.

## Изоляция сохранений

- Вспомогательная веб-оболочка при `?test=1` не монтирует IndexedDB: файловая система теста остаётся в памяти, а пользовательский прогресс сайта не затрагивается. Обычный режим использует постоянное хранилище.
- Сам GDScript-набор перед тестом запоминает настройки и байты исходного сохранения, после успешного завершения восстанавливает их.
- По завершении тест возвращается в меню; нативный headless-режим завершает процесс с соответствующим кодом.

## Windows-лаунчер

Пересобран однофайловый x64 PE-исполняемый файл из Node.js `v22.22.3` (Windows npm-пакет проверен по закреплённой SHA-512), SEA-blob и файлов Godot Web runtime; размер — **127,432,192 байта**. PE Subsystem переведён в GUI, чтобы не показывать пустую консоль. Вместо открытия обычной вкладки код запускает установленный Edge (при его отсутствии — Chrome) с `--app=<локальный URL>`: ожидается отдельное окно без вкладок и адресной строки. Для игровых сохранений используется обычный профиль браузера.

Вложенные index.html / JS / WASM / PCK извлечены из предыдущего проверенного артефакта и включены в пересобранный exe; PCK содержит ту же версию игры, которая прошла 816 проверок Godot Web в Chromium 138. Синтаксис Node-лаунчера и сборочный скрипт проверены. Исходный лаунчер на Linux проверен запросами `/__health` и `HEAD /index.wasm`, POST `/__quit` закрыл сервер; сама Linux-проверка не может открыть Edge app mode. Сам новый PE, запуск Edge/Chrome в режиме приложения и закрытие окна **не запускались на реальной Windows-машине**: среды Windows/Wine здесь нет. Это WebAssembly-игра в отдельном окне Chromium, а не нативный экспорт Godot Win64; нужен Edge или Chrome с WebGL 2. Не подписан Authenticode.

## Что пока не проверено

- Запуск **нативных** сборок Windows/Linux: в среде разработки не было настольного бинарника Godot. Подготовлены исходники и пресеты, не готовые `.exe`/AppImage.
- Официальный экспорт из редактора и запуск в Godot **4.5**. Используемые API рассчитаны на 4.5+, но фактический runtime теста — **4.6**. Для первого запуска рекомендуется 4.6.
- Производительность на реальных ПК/телефонах, Safari/iOS, геймпады, изменение аудиоустройств.
- Ручное прохождение всей кампании без тестовых перемещений/ускорения переходов. Ключевые условия победы, смерти и прогрессии проверены автоматикой.
- Длительные многочасовые сессии, полный аудит доступности и окончательный баланс.

## Повторение проверки

Из исходного проекта:

```sh
godot --headless --path . -- --smoke-test
```

Из уже запущенного вспомогательного веб-предпросмотра:

```sh
python3 tools/pack_preview.py
python3 tools/browser_check.py --test
python3 tools/browser_check.py --play --screenshot artifacts/game.png
```

Для первого запуска `pack_preview.py` нужны `index.js`/`index.wasm` одной версии Godot, указанные через `--template`. `browser_check.py` требует Playwright и Chromium. По умолчанию он проверяет `http://127.0.0.1:8080`; адрес можно изменить через `--url`, браузер — через `CHROMIUM_PATH`.
